# gtd-coach

Роль коуча по личной эффективности для Claude Code: **как коуч работает** —
конституция, методология, правила работы с памятью, навыки, хуки и объявления
инструментов.

Того, **что коуч знает про человека**, здесь нет и не будет: это приватная
память, отдельный репозиторий, свой у каждого.

## Что это за коуч

Он живёт в телеграме и **помнит вас**. Три раза в день пишет первым: утром —
что главное сегодня и что вы обещаете сделать, днём — как идёт обещанное,
вечером — что вышло. Раскладывает наговоренное по задачам и календарю сам,
не заставляя открывать приложение. Раз в неделю подводит итог, раз в месяц
сверяет жизнь со стратегией. И копит понимание про вас — что работает, что
бесит, в какие часы вы правда закрываете дела, — а не начинает каждый раз
с нуля.

**Дверь к нему одна — телеграм.** Компьютер нужен как верстак: поставить,
обновить, изредка заглянуть в память глазами или откатить запись. Разговаривать
с коучем оттуда нельзя, и это не недоделка: у него один непрерывный разговор
с закладкой, и второй собеседник, пишущий в ту же память, её разъезжает.
Это уже прожито и стоило дорого.

## Как развернуть — один способ

> **Не программисту сюда:** [`УСТАНОВКА.md`](УСТАНОВКА.md). Ни одной команды
> набирать не надо — всё делает Claude Code, а вы отвечаете на вопросы.
> Скажите ему: «изучи репозиторий https://github.com/vefmvai/gtd-coach, прочитай
> `УСТАНОВКА.md` и разверни мне этого коуча, веди по шагам».

Ниже — то же самое для тех, кто ставит руками. Четыре шага, всё, кроме
первого, делается один раз.

**1. Что понадобится**

| Что | Зачем | Цена |
|---|---|---|
| Сервер с Docker (любой VPS) | там живёт бот и его память | от пары долларов в месяц |
| Бот в телеграме | ваша дверь к коучу | бесплатно, через [@BotFather](https://t.me/BotFather) |
| Подписка Claude или ключ API | этим коуч думает | по вашему тарифу |
| Аккаунт Todoist | дела | бесплатного тарифа хватает целиком |
| Аккаунт Google (по желанию) | календарь | бесплатно |
| Ключ Groq или OpenAI | расшифровка голосовых | у Groq есть бесплатный тир |

**2. Завести себе приватный репозиторий памяти**

Пустой скелет с объяснениями «что сюда кладут» лежит здесь же, в
[`brain-template/`](brain-template/). Скопируйте его в свой **приватный**
репозиторий — это и будет мозг коуча.

Приватный обязательно: туда попадёт всё, что коуч про вас поймёт.

**3. Поднять бота**

Подробные шаги, переменные и объяснения — в
[`gtd-coach-bot`](https://github.com/vefmvai/gtd-coach-bot). Коротко:

```bash
git clone git@github.com:vefmvai/gtd-coach-bot.git /opt/apps/gtd-coach-bot
cd /opt/apps/gtd-coach-bot
cp .env.example .env && vim .env       # токены, в файле про каждый написано
git clone <ваш-приватный-репозиторий-памяти> data/brain
git clone https://github.com/vefmvai/gtd-coach.git /opt/apps/gtd-coach-plugin
git clone https://github.com/vefmvai/todoist-mcp.git /opt/apps/todoist-mcp
git clone https://github.com/vefmvai/gcal-mcp.git   /opt/apps/gcal-mcp
./update.sh                            # первая сборка — той же командой, что и обновления
```

Календарь можно не клонировать — тогда коуч будет без него, и команда
обновления на это не пожалуется.

**4. Познакомиться**

Напишите боту `/start`, потом — «давай знакомиться». Дальше он поведёт сам:
навык **онбординга** расскажет про подход (миссия, ценности, горизонты, колесо
баланса), объяснит, что он про вас помнит и во что пишет, и по ходу разговора
наполнит пустой скелет памяти вашими ответами. Ничего заполнять руками не надо
и не нужно: он не выдумывает за вас ни строчки.

### Как обновляться

**GTD-коуч — это продукт из нескольких частей, и обновляются они вместе.**

| Часть | Что это |
|---|---|
| бот | докер и телеграм: [`gtd-coach-bot`](https://github.com/vefmvai/gtd-coach-bot) |
| плагин | роль, навыки, методология — этот репозиторий |
| `todoist-mcp` | инструменты списка дел |
| `gcal-mcp` | инструменты календаря (можно не ставить) |
| движок | Claude Code внутри бота |

Мозг сюда не входит: он ваш, лежит в вашем приватном репозитории, и никакое
обновление его не трогает.

Одна команда на сервере, в папке бота:

```bash
./update.sh
```

Она тянет каждую часть, пересобирает образ, если надо, поднимает контейнер
и печатает, что приехало. Что стоит сейчас — команда **`/version`** в телеграме.

Помнить про обновления не нужно: **каждую ночь бот сверяет все части с GitHub
сам** и, когда выходит новое, ставит задачу в ваш Todoist. Одну на повод.

Версия движка Claude Code обновляется отдельно и руками — она запинена
намеренно, чтобы мозг коуча не менялся побочным эффектом сборки.

### Что необязательно

| Не поставили | Что перестанет быть | Что при этом работает |
|---|---|---|
| `gcal-mcp` и ключи Google | календарь: события, свободные окна, «занято во времени» | всё остальное; коуч перестанет учитывать занятое время при планировании дня |
| ключ Groq / OpenAI | голосовые: расшифровки не будет | текст, кнопки, ритуалы |
| Todoist | дела: без них коуч превращается в собеседника без рук | разговор и память |

Календарь выключается сам: нет настроек — нет и календарных кнопок, коуч
про них даже не знает. Команда обновления не склонированную часть пропускает
молча и на её отсутствие не жалуется.

### Верстак: плагин на своём компьютере

Он нужен, только если хотите править роль коуча или смотреть память глазами:

```
/plugin marketplace add vefmvai/claude-plugins
/plugin install gtd-coach@vefmvai
```

Во время правок удобнее видеть изменения сразу, без переустановки:

```bash
claude --plugin-dir ./plugin
```

## Как докрутить под себя — три слоя

Почти всё, что хочется поменять, меняется **словами в телеграме**. Лезть
в код нужно редко, и это сделано намеренно.

### Слой 1: словами в телеграме — девять случаев из десяти

Просто скажите коучу, он поправит сам и покажет, что изменил:

| Хочу | Скажите |
|---|---|
| писать мне в другое время, реже, не дёргать вечером | «пиши мне в 9 утра», «не дёргай после девяти» |
| думать другой моделью | «переключись на Opus» |
| убрать ненужную кнопку инструмента | «выключи статистику» |
| взять с собой больше или меньше памяти | «проведём недельный обзор» (режим переключит код) |
| поправить факт о себе | «запомни: я перестал вести инстаграм» |
| подсказать распознавателю мои слова | «ты расшифровал неверно, пишется так: Кинешма» |
| попросить умение, которого нет | «хочу, чтобы ты умел X» — ляжет в заявки |

Всё это — **данные в вашей памяти**, а не код: `ритмы.md`, `настройки.md`,
`знания/`. Коуч правит их прямо в разговоре, и работает это со следующей
реплики — без перезапуска.

### Слой 2: файлом в мозге — личная надстройка к роли

Хотите, чтобы коуч всегда вёл себя как-то по-своему, а не в рамках общей роли?
Заведите `память/состояние/личная-надстройка.md` и напишите туда своими
словами. Код подклеивает этот файл **после** общей конституции: расходится
с общей частью — побеждает ваша.

Туда идёт то, что должно действовать всегда: как к вам обращаться, каким
языком говорить, чего не делать никогда.

**Почему в мозге, а не в плагине.** Плагин — это то, что можно снести и
поставить заново, ничего не потеряв. Claude Code кладёт его в папку, названную
версией (`cache/…/gtd-coach/0.1.0/`); новая версия — новая папка, и файл,
положенный в старую, не затирается, а просто перестаёт читаться. Тихая пропажа
без единой ошибки в логах. Мозг обновлением не сносится никогда.

### Слой 3: правкой плагина — когда меняется сама работа коуча

Новый навык, другая методология, другой состав режимов контекста. Это уже
код: правится в клоне плагина, приезжает на сервер через `git pull` и рестарт
контейнера.

Граница между слоями простая: **меняется знание про вас или настройка —
телеграм; меняется устройство коуча — плагин.**

## Что внутри

| Папка | Что там |
|---|---|
| `prompts/конституция/` | четыре части конституции — ядро, память, стратегия, ритуалы; код склеивает нужные под режим |
| `prompts/` | остальные тексты поведения: чек-ины, дожимы, ночные выжимки, предложение обзора |
| `режимы.md` | что коуч берёт с собой в разговор: состав четырёх режимов контекста |
| `methodology/` | как именно работать: стратегия, работа в списке дел |
| `skills/` | навыки: знакомство, правка памяти, недельный обзор, месячный итог |
| `brain-template/` | пустой скелет памяти с объяснениями «что сюда кладут» |
| `hooks/` | проверка записи в память и свежести правил |
| `standard/` | стандарт памяти — копия, доступная боту в контейнере |
| `scripts/` | пусковые скрипты инструментов |
| `.mcp.json` | объявление инструментов: список дел и календарь |

**Чего здесь нет:** питон-движка, docker, телеграма, `.env`, самой памяти
и чьих-то личных правил. Плагин описывает работу, а не человека, — и это
проверяется тестом, а не обещанием (`tests/`).

## Инструменты

Плагин объявляет два MCP-сервера, и они приезжают вместе с ним:

| Сервер | Что даёт | Репозиторий |
|---|---|---|
| `todoist` | задачи, подзадачи, комментарии, структура, фильтры, статистика | [`todoist-mcp`](https://github.com/vefmvai/todoist-mcp) |
| `calendar` | события, поиск, свободные окна, несколько календарей | [`gcal-mcp`](https://github.com/vefmvai/gcal-mcp) |

Сами серверы — отдельные пакеты: это инструменты к сервисам, а не части
коуча, и звать их может любой агент.

### Что нужно, чтобы они заработали

Секреты берутся по цепочке: сначала переменные окружения, потом связка
ключей macOS. В конфиг и в репозиторий они не попадают ни в одном случае.

```bash
# Список дел
TODOIST_API_TOKEN=…            # либо запись в связке ключей
TODOIST_MCP_PYTHON=…           # python, которому доступен пакет todoist-mcp

# Календарь
GOOGLE_CLIENT_ID=…
GOOGLE_CLIENT_SECRET=…
GOOGLE_REFRESH_TOKEN=…
GCAL_MCP_PYTHON=…              # python, которому доступен пакет gcal-mcp
```

Вместо `*_MCP_PYTHON` можно задать `TODOIST_MCP_SOURCE` / `GCAL_MCP_SOURCE` —
источник для `uvx`, и тогда ставить пакеты заранее не нужно.

Имена записей в связке ключей меняются переменными `TODOIST_KEYCHAIN_ITEM`,
`GOOGLE_KEYCHAIN_CLIENT_ID` и подобными; умолчания — в самих скриптах
(`scripts/todoist.sh`, `scripts/calendar.sh`).

### Тумблеры: что грузить в сессию

Описание каждой кнопки уезжает в контекст модели. Для одноразовой сессии это
ничего не стоит. Для агента, у которого контекст копится — память, цели,
история, — стоит вниманием модели, и платит он им всегда.

Поэтому набор выбирает тот, кто платит:

```yaml
# ~/.config/todoist-mcp/tools.yaml
tools:
  productivity_stats: off
  manage_filters: off
```

Два правила:

- **кнопки нет в файле — она включена.** Обновились, приехала новая
  возможность — работает сразу. Молча пропавшую кнопку ищут неделями,
  лишнюю выключают за десять секунд;
- **выключенная кнопка не объявляется вообще** — то есть не занимает места.
  Тумблер, который не экономит место, был бы украшением.

Посмотреть, что получилось, — командой. Таблица печатается из кода, а не
из документации, поэтому не может устареть:

```bash
python -m todoist_mcp.table    # кнопки, тариф, что грузится
python -m gcal_mcp.table
```

У бота те же тумблеры лежат в его памяти и меняются разговором: «выключи
статистику» — и со следующей реплики её нет.

### Про платные возможности списка дел

Всё построено под **бесплатный тариф**: платить, чтобы пользоваться коучем,
не нужно.

Часть возможностей Todoist платная, и ведут они себя одинаково скверно —
одна роняет запрос целиком, другая молча выбрасывает данные. Поэтому тариф
спрашивается у самого сервиса при запуске, а недоступное **не предлагается
модели вовсе**: нет фичи — нет поля, и промахнуться нечем.

## Проверить, что личного здесь нет

```bash
python3 -m pytest tests/ -q
```

Сторож обходит все файлы репозитория и краснеет на имени, адресе или названии
чужого проекта. Заведён потому, что обезличивание — разовая работа, а
репозиторий живёт дальше: правило без прибора не выполняется.
