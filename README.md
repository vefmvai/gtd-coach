# gtd-coach

Плагин Claude Code: **роль коуча по личной эффективности**. Здесь лежит то,
**как коуч работает** — конституция, методология, правила работы с памятью,
навыки, хуки и объявления инструментов.

Того, **что коуч знает про подопечного**, здесь нет и не будет: это приватная
память, отдельный репозиторий, свой у каждого владельца.

## Зачем плагин, а не файлы рядом с кодом

Коуч живёт в двух каналах — телеграм-бот на сервере и обычная сессия
Claude Code. Пока конституция лежала файлом внутри бота, одни и те же правила
оказывались записаны дважды: в промпте бота и в правилах памяти. Правишь
одно — второе молча врёт.

Плагин делает из этого один дом. Обе стороны читают его же файлы.

## Что внутри

| Папка | Что там |
|---|---|
| `prompts/` | конституция коуча и все тексты его поведения: чек-ины, дожимы, ночные выжимки, месячный итог |
| `methodology/` | как именно работать: стратегический курс, работа в списке дел |
| `skills/` | навыки: правка памяти, недельный обзор, месячный итог |
| `hooks/` | проверка записи в память и свежести правил |
| `standard/` | стандарт памяти — копия, которую читают оба канала |
| `scripts/` | пусковые скрипты инструментов |
| `.mcp.json` | объявление инструментов: список дел и календарь |

## Инструменты

Плагин объявляет два MCP-сервера, и они приезжают вместе с ним — отдельно
настраивать ничего не нужно:

| Сервер | Что даёт | Репозиторий |
|---|---|---|
| `todoist` | задачи, подзадачи, комментарии, структура, фильтры, статистика | `todoist-mcp` |
| `calendar` | события, поиск, свободные окна, несколько календарей | `gcal-mcp` |

Сами серверы — отдельные пакеты: это инструменты к сервисам, а не части
коуча, и звать их может любой агент.

### Что нужно, чтобы они заработали

Секреты берутся по цепочке: сначала переменные окружения, потом связка
ключей macOS. В конфиг и в репозиторий они не попадают ни в одном случае.

```bash
# Список дел
TODOIST_API_TOKEN=…            # либо запись в связке ключей
TODOIST_MCP_PYTHON=…           # python, которому доступен пакет todoist-mcp

# Календарь
GOOGLE_CLIENT_ID=…
GOOGLE_CLIENT_SECRET=…
GOOGLE_REFRESH_TOKEN=…
GCAL_MCP_PYTHON=…              # python, которому доступен пакет gcal-mcp
```

Вместо `*_MCP_PYTHON` можно задать `TODOIST_MCP_SOURCE` / `GCAL_MCP_SOURCE` —
источник для `uvx`, и тогда ставить пакеты заранее не нужно.

Имена записей в связке ключей меняются переменными `TODOIST_KEYCHAIN_ITEM`,
`GOOGLE_KEYCHAIN_CLIENT_ID` и подобными; умолчания — в самих скриптах
(`scripts/todoist.sh`, `scripts/calendar.sh`).

### Тумблеры: что грузить в сессию

Описание каждой кнопки уезжает в контекст модели при каждом запуске.
Замер на живом боте: около **570 байт на кнопку**, а кнопок два десятка.
Для одноразовой сессии это ничего не стоит. Для агента, у которого контекст
копится — память, цели, история, — стоит, и платит он этим местом всегда.

Поэтому набор выбирает тот, кто платит:

```yaml
# ~/.config/todoist-mcp/tools.yaml
tools:
  productivity_stats: off
  manage_filters: off
```

Два правила:

- **кнопки нет в файле — она включена.** Обновились, приехала новая
  возможность — работает сразу. Молча пропавшую кнопку ищут неделями,
  лишнюю выключают за десять секунд;
- **выключенная кнопка не объявляется вообще** — то есть не занимает места.
  Тумблер, который не экономит место, был бы украшением.

Посмотреть, что получилось, — командой. Таблица печатается из кода, а не
из документации, поэтому не может устареть:

```bash
python -m coach_todoist_mcp.table    # кнопки, тариф, что грузится
python -m gcal_mcp.table
```

У коуча-бота те же тумблеры лежат в его памяти, и меняются они разговором:
«выключи статистику» — и со следующей реплики её нет.

### Про платные возможности списка дел

Всё построено под **бесплатный тариф**: платить, чтобы пользоваться коучем,
не нужно.

Часть возможностей Todoist платная, и ведут они себя одинаково скверно —
одна роняет запрос целиком, другая молча выбрасывает данные. Поэтому тариф
спрашивается у самого сервиса при запуске, а недоступное **не предлагается
модели вовсе**: нет фичи — нет поля, и промахнуться нечем.

Что даёт платный тариф, покажет та же команда `table` — она берёт ответ
у сервиса, а не из текста, который однажды устареет.

## Чего здесь нет

Питон-движок, docker, телеграм, `.env`, сама память, личные правила
владельца. Плагин описывает работу, а не человека.

## Как ставится

Из каталога плагинов:

```
/plugin marketplace add vefmvai/claude-plugins
/plugin install gtd-coach@vefmvai
```

Во время доработки удобнее видеть правки сразу, без переустановки:

```
claude --plugin-dir ./plugin
```

**Боту** плагин приезжает смонтированным клоном, только на чтение: каталог
контейнер не умеет — движок в нём принимает лишь локальный путь. Клон
обновляется `git pull`, контейнер перезапускается. Рестарт обязателен:
новый плагин подхватывается на следующей сессии, а не мгновенно.
