# gtd-coach

Плагин Claude Code: **роль коуча по личной эффективности**. Здесь лежит то,
**как коуч работает** — конституция, правила работы с памятью, навыки, хуки.

Того, **что коуч знает про подопечного**, здесь нет и не будет: это приватный
мозг, отдельный репозиторий, свой у каждого владельца.

## Зачем плагин, а не файлы рядом с кодом

Коуч живёт в двух каналах — телеграм-бот на сервере и сессия Claude Code
в мастерской. Пока конституция лежала файлом внутри бота, одни и те же правила
оказывались записаны дважды: в промпте бота и в правилах мозга. Правишь одно —
второе молча врёт.

Плагин делает из этого один дом. Обе стороны читают его же файлы.

## Что внутри

| Папка | Что там |
|---|---|
| `prompts/` | конституция коуча — системный промпт роли |

Навыки (`skills/`) и хуки (`hooks/`) появятся, когда появится первый настоящий
навык. Пустых папок «на будущее» здесь нет намеренно: механизм заводится под
названный случай, который без него ломается.

## Чего здесь нет

Питон-движок, docker, телеграм, `.env`, мозг, личные правила владельца.
И **MCP-серверы**: у коуча они не внешние программы, а объекты, которые движок
собирает у себя внутри. Плагин умеет объявить сервер командой запуска — здесь
запускать нечего.

## Как ставится

**В мастерской** — из маркетплейса:

```
/plugin marketplace add vefmvai/claude-plugins
/plugin install gtd-coach@vefmvai
```

Во время разработки удобнее видеть правки сразу, без переустановки:

```
claude --plugin-dir ./plugin
```

**Боту** — смонтированным клоном, только на чтение. Маркетплейс контейнер
не умеет: движок в нём принимает лишь локальный путь. Клон на сервере
обновляется `git pull`, контейнер перезапускается — оба шага делает `deploy.sh`
лаборатории. Рестарт обязателен: новый плагин подхватывается на следующей
сессии, а не мгновенно.
